## Why
Lesson #1 from the empirical observation: Radar's agent interface is a set
of text files an agent reads in a single call — half the lookups never even
go through the binary. That is what makes the product token-efficient.
We adopt the pattern.

## What
`rr map` also emits: `MAP.md` (root, committed) and `.rr/SYMBOLS.md`
(committed as well — a divergence from Radar which gitignores it: a
versioned public index benefits the whole team and CI agents).

## How
1. `MAP.md`: minimal YAML frontmatter
   `{type, scope, api_hash, tokens: ~N, stamped}` then:
   - a free-form descriptive slot `<!-- rr:slot purpose max=160 -->…<!-- /rr:slot -->`
     pre-filled by heuristic (top terms), preserved as-is on regenerations
     if a human/agent has edited it (parse the slot before writing);
   - `## API` section: public signatures grouped by file;
   - `## Tests` section: test files.
   Hard budget: if the API exceeds ~250 estimated tokens, switch to one
   MAP.md per directory (tree) — V1: a single root level + a warning.
2. `api_hash`: hash of the sorted public signatures — changes iff the
   public API changes. It is the invalidation key for routes (issue 12).
3. `.rr/SYMBOLS.md`: one sorted line per public symbol:
   `verify_token → src/auth/token.rs#9` (no map column in V1).
4. Deterministic regeneration: same index ⇒ same byte-identical file
   (otherwise diff noise on every commit — golden test).
5. Merge conflict on MAP.md: document the Radar rule (pick one side,
   `rr map`, commit) in the file itself (HTML comment at the bottom).

## Best practices
- Estimate tokens with `len/4` — no tokenizer dependency.
- All generated content carries a `generated by rr` marker + version.

## Acceptance criteria
- [ ] Fixture MAP.md ≈ 200 tokens, empty diff on re-run without changes.
- [ ] Manually edited slot → preserved after `rr map`.
- [ ] `api_hash` insensitive to a body change, sensitive to a signature.
- [ ] SYMBOLS.md sorted, greppable, up to date.
